安全架构
========

X1 安全设计以硬件信任根为起点，覆盖启动验证、固件和数据保护、设备身份、安全通信与
软件物料治理。说明书给出的目标面向 IEC 60730 功能安全和 IEC 62443 网络安全要求；
具体产品是否满足认证，仍取决于硬件设计、量产流程、密钥管理和应用软件的完整实现。

.. container:: module-summary security-summary

   **纵深防护路径**

   ``eFuse 信任根`` → ``BootROM`` → ``一级/二级 BootLoader`` → ``内核与根文件系统`` → ``应用``

   每一级只加载通过签名验证的下一级镜像，固件密钥和设备秘密由受限硬件区域保存。

安全信任链
----------

eFuse 规划包含芯片唯一 ID、根公钥哈希 ``ROT_PK_HASH``、固件解密密钥
``SPI_ENC_KEY``、设备秘密 ``DEVICE_SECRET`` 和锁定位。量产时应先烧录并校验数据，
最后设置读写保护；锁定位通常不可逆，必须通过样片流程验证烧录脚本。

安全启动
--------

.. image:: /_static/img/manual/secure-boot.png
   :alt: X1 安全启动验证链
   :class: manual-figure manual-figure-narrow
   :align: center

启动链的关键职责如下：

* BootROM 使用 eFuse 中的根信息验证并解密一级 BootLoader。
* 一级、二级 BootLoader 逐级验证系统镜像，验证失败时不得跳转执行。
* 内核阶段继续保护关键模块和文件系统完整性，再启动应用服务。

.. important::

   当前说明书明确指出 **暂不支持回滚保护**。升级流程不会根据版本号阻止降级，
   因此版本策略、云端授权和发布审批不能替代芯片级防回滚能力。

数据与设备保护
--------------

.. container:: capability-list

   * **防抄板**：固件在 Flash 中加密保存，并使用每设备秘密派生身份和数据密钥。
   * **防读取**：量产阶段锁定调试入口，敏感密钥仅允许安全硬件使用。
   * **防篡改**：启动与运行阶段校验关键镜像和配置，敏感数据写入加密分区。
   * **隐私保护**：对外使用派生设备标识，工厂重置时清除用户数据分区。
   * **安全传输**：业务链路使用 TLS/DTLS 和设备证书进行服务端或双向认证。

量产检查清单
------------

1. 为开发、试产和量产建立隔离的根密钥与签名权限。
2. 在烧录 ``LOCK_BITS`` 前回读并验证公钥哈希、设备秘密和加密密钥状态。
3. 禁止在日志、崩溃转储或测试接口中输出密钥、令牌和完整设备身份。
4. 验证签名失败、断电升级、分区损坏、证书过期和工厂重置等异常路径。
5. 为发布固件生成 CycloneDX SBOM，并对第三方库许可证与已知漏洞持续跟踪。

.. code-block:: console
   :caption: 生成 CycloneDX SBOM 的示例

   syft dir:output/target -o cyclonedx-json > sbom_cyclonedx.json
