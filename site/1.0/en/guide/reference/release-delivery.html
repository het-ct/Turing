Versions, Downloads and Deliverables

Het-X1 SDK delivery should use source code, tools, hardware information and version records as the same set of controlled baselines. Don’t just send a firmware file, otherwise the recipient won’t be able to confirm that the toolchain, board, and resource versions match.

Suggested deliverables

MCU SDK delivery list

category

content

Verification method

SDK source code

platform, target projects, build script and dependency declaration

Complete a full compilation from a clean directory

firmware

app.dcf, check value, version number and applicable board type

Check the startup log and functional smoke test after burning

tool

Compilation chain, burner, X1 toolbox and version notes

Record tool versions and verify commands are executable

Hardware information

Schematic, PCB constraints, BOM/AVL, package and board version

Cross-check with physical silk screen and engineering configuration

document

Offline packages, APIs, change records and known issues of this site

After unzipping, check the Chinese and English links from index.html

version rules

Release records include at a minimum the SDK version, Git commit, build date, toolchain version, supported boards, known limitations, and upgrade compatibility. When firmware, resources and configurations change respectively, their compatibility relationship should be clarified. The document version is managed by doc_versions of metadata.json. For the construction method, please refer to the document release instructions of the project.
