OTA upgrade

Overview

The OTA process defined in the manual is: wireless connection, reading version, initiating upgrade request, sending firmware package, verification and restart. The current interface is named het_ota_*, supports writing firmware and resources to Flash/SD card, and completes trial run confirmation according to A/B partition or MCUBOOT SWAP strategy.

Usage process

  1. Read the current execution partition and device version.

  2. Download to inactive partition, recording offset, length and verification status during transfer.

  3. Complete image summary/signature verification and reject packages with mismatched versions, board types, or resources.

  4. Set up a temporary execution partition and restart the test run.

  5. The new firmware will confirm the partition after passing the startup self-test; if it fails, the old partition will remain bootable.

Example

int ota_finish(void)
{
    int part = het_ota_get_current_partition();
    if (part < 0) return part;
    if (het_ota_double_check_for_execution() < 0) return HET_FAIL;
    return het_ota_accept_image();
}

Things to note

  • Download interruptions, power outages, insufficient space, verification failures and low battery must be recoverable.

  • The current data annotation does not support version rollback protection, and the A/B partition confirmation cannot be mistaken for hardware rollback prevention.

  • The upgrade package should be bound to the chip/board, firmware, UI resources and configuration version.

  • The mass production upgrader, partition table, signing tool and forced recovery process are to be developed.

Main API

het_ota_get_current_partition, het_ota_register_temp_partition_callback, het_ota_confirm_update_partition, het_ota_accept_image, het_ota_start_download, het_ota_double_check_for_execution, het_ota_write_flash and het_ota_temp_execute_partition.

For interface signature, parameters and return values, see Service API。
