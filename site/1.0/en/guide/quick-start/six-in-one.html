Six-in-one development kit

Development board overview

The six-in-one development kit uses the Het-X1 core board as the control core for centralized verification of display and touch, audio input and output, cameras, Bluetooth/Wi-Fi, sensors and common control peripherals. The kit is suitable for evaluating chip capabilities, running HAL examples, and building production board configurations, and should not be used as a direct replacement for electrical and reliability verification of production hardware.

Before powering on, confirm the core board model, backplane version, display and touch module, power input, debugging serial port and jumper position. For S1 core board interface information, see Packaging and development board；S2、S3 complete package information to be developed.

Source code or firmware acquisition

The current warehouse already contains SDK source code, projects/watch320, projects/haier_hmi and peripheral examples. The delivery package should contain at least:

  • platform: HAL, BSP, middleware, services and examples.

  • projects: Compilable product or demonstration project.

  • Compilation tool chain, burning tools, board information, version records and known issues.

  • Firmware Output/bin/app.dcf has been built and its applicable board descriptions.

The official download address, historical version archive and verification list are to be developed and should currently be obtained from the controlled delivery package provided by the project leader.

Environment setup

Install the compilation chain, Python, VS Code, serial port driver and plug-in, see Environment setup。. After completion, compile the existing project:

cd .\projects\watch320
python gen-srclist.py
make

Firmware or program download

  1. Confirm that the target board type, chip package and config.h configuration are consistent.

  2. Close the serial port assistant occupying the download serial port, connect the development board and enter download mode.

  3. Select Output/bin/app.dcf in the supporting Downloader, check the port and start downloading.

  4. Reset the development board, reopen the serial terminal, and check the version, reset reason, and startup log.

  5. Verify display, touch, audio, camera, communications, and target peripherals in order.

Warning

There is no controlled public description of the download tool’s port parameters, startup pin level, encrypted burning, and failure recovery steps, and remains to be developed. Do not modify the security configuration or erase unknown partitions before the mass production process is released.
