软件架构与分层
==============

概述
----

Het-X1 采用自底向上的分层设计。每一层只依赖下一层提供的稳定能力，上层通过接口和回调使用下层，
避免业务代码直接访问寄存器、芯片启动代码或具体器件驱动。这样可以在更换封装、显示器件或 RTOS 时，
只调整适配层，不重写产品业务。

   :alt: Het-X1 软件分层架构
   :class: manual-figure

分层职责
--------

* **L1 芯片与 SoC**：提供 CPU、存储、时钟、中断和片上控制器等硬件资源。
* **L2 外设 HAL/BSP**：将 GPIO、UART、IIC、SPI、LCD、定时器等硬件抽象为统一接口，并完成板级管脚、
  电源和时钟适配。
* **L3 OS/OSAL**：提供线程管理、任务通信、软件定时器、内存和临界区等系统服务，隔离具体操作系统。
* **L4 中间件**：提供 GUI、文件系统、数据库、协议栈和传感器框架等通用能力。
* **L5 CBB 能力组件**：把音频、蓝牙、算法、日志、安全存储等能力封装为可组合模块。
* **L6 产品应用**：完成页面、业务状态机、设备策略和产品配置，不直接操作底层寄存器。

职责边界与原则
--------------

依赖方向始终为 L6 → L5 → L4 → L3 → L2 → L1。跨层访问应通过公共头文件、配置项或注册回调完成；
同层模块保持独立，资源所有权和生命周期由创建者明确管理。中断只做清状态、采样和投递事件，耗时处理
放到任务或主循环。存储分区和代码段规划见 :doc:`memory`，板级选择见 :doc:`board-config`。

OSAL 边界
---------

OSAL 对上层提供与操作系统无关的线程、队列、互斥锁、软件定时器、堆分配和临界区接口；对下层负责适配
具体调度器、系统节拍、中断和内存实现。当前仓库尚未提供完整统一的 OSAL 移植包，缺失的线程调度器、
队列后端和端口适配标记为 **待开发**，应用不得绕过 OSAL 直接依赖某个 RTOS 原生类型。
