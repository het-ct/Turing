CBB capability components

Overview

CBB encapsulates algorithms, communications, or system capabilities into reusable components. Components should expose explicit configuration, input events, output events, and life cycles, and should not occupy board-level resources implicitly.

Component Catalog

Existing topics include audio algorithms, Bluetooth communication, CANopen, IMU, infrared, charging, logging, Modbus, motors, RGB lights, secure storage, USB, vision and Wi-Fi. For the entrance, see CBB capability components。Each topic page should describe dependencies, initialization, input/output, error recovery, and examples；The ability to stabilize header files without the het prefix in the repository remains to be developed。

How to use

  1. Confirm the dependent HAL, BSP, middleware and memory budget on the Components page.

  2. Allocate buses, DMA, tasks and buffers in board configuration.

  3. After initialization, the event callback is registered, and the input is processed by the task cycle.

  4. Design recovery paths for disconnections, timeouts, data corruption, and insufficient resources.

  5. Release callbacks, tasks, and peripheral resources after stopping the component.

Example

int app_component_start(void)
{
    cbb_config_t cfg = cbb_default_config();
    cfg.event_cb = app_on_cbb_event;
    return cbb_init(&cfg); /* 通用接口形式，具体名称以组件头文件为准。 */
}

Main API

For topics on audio, vision, IMU, motors, Bluetooth, Wi-Fi, USB, infrared, Modbus, CANopen, lighting effects, charging, logging and secure storage, see CBB capability components。Components that do not provide stable header files in the repository are still marked as pending development。
