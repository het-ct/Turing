Board level configuration config.h

Overview

Each product project selects chip packaging, clock, storage, display, touch, communication and business functions through projects/<project>/config.h. Currently, you can refer to projects/watch320/config.h and projects/haier_hmi/config.h, but their parameters cannot be directly reused across boards.

Configuration process

  1. Document packaging, power, Flash/PSRAM, display, touch and debug serial ports from the target board schematic.

  2. Copy the closest project configuration and turn off functions unrelated to the target board first.

  3. Configure CHIP_PACKAGE_SELECT, SYS_CLK_SEL, FLASH_* and NOC_PSRAM_*.

  4. Configure GUI_SELECT, CTP_SELECT and corresponding reset, interrupt, backlight and bus pins.

  5. Execute python gen-srclist.py, check the generated source code and header file list, and then compile it in full.

Configure dependency order

It is recommended to modify in the order of “Chip and Clock → Flash/PSRAM → Pin Multiplexing → Display/Touch → Communication/Audio → Function Tailoring → UI Resources”. Do not enable high-level functions before the pre-configuration is confirmed. For example, do not enable pages or complex special effects directly before the LCD and touch pins, power supplies, and buses are verified.

config.h only saves the product selection and does not directly put it into the initialization process. The initialization sequence should be implemented in the project entry or the corresponding BSP to avoid repeated initialization of the same peripheral due to scattered macro switches.

Things to note

Draw the address map before modifying the partition; verify the touch coordinates after modifying the screen parameters; retest UART, IIC, SPI, LCD and audio sampling after modifying the clock. There are still some historical annotations in the configuration file that are encoded abnormally. Options with unclear meanings should be confirmed with the module leader.

  • gen-srclist.py must be re-executed after modifying FUNC_*_EN, GUI_USE_* or resource options, otherwise the source code manifest may still refer to the old module.

  • Record the board version, config.h submission, firmware version and test results for each change to avoid misdiagnosing runtime problems as driver problems.

Example

#define SYS_CLK_SEL       SYS_192M
#define FLASH_SIZE        FSIZE_16M
#define GUI_SELECT        GUI_TFT_480_272_ST6201
#define CTP_SELECT        CTP_GT911
#define UART0_PRINTF_SEL  PRINTF_PB3

After completing the configuration, check the initialization sequence of the onboard devices at Drivers and BSP and review the pin definitions at Pin definition and reuse.
