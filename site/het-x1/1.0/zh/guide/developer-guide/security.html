系统安全

安全架构

本节依据《图灵平台使用说明书》1.3 “X1 安全架构”整理。安全目标包括固件机密性与完整性、设备身份保护、 敏感数据安全存储、防篡改和通信安全。安全策略应从启动链、存储分区、密钥生命周期和量产流程整体设计， 不能只在应用层增加校验。

信任根与固件保护

X1 使用 eFuse 保存设备级密钥和安全配置。BootROM/BootLoader 对 Flash 中的固件执行签名校验，固件可使用 SPI_ENC_KEY 加密存储，并在运行时解密到 RAM。eFuse 一旦写入通常不可逆，必须在受控量产工位操作。

安全存储与防篡改

Wi-Fi 密码、用户令牌等敏感数据应加密存放在 USER_DATA 分区；关键 SPI Flash 总线可启用总线加扰。 芯片支持主动防拆检测，检测到外壳打开等事件时可触发密钥擦除。安全存储 CBB 的具体密钥管理接口仍需结合 产品方案，缺失部分 待开发。

安全通信与隐私

设备证书可由 DEVICE_SECRET 派生并存放于安全区域；网络连接使用 TLS/DTLS，并执行服务端证书校验。 对外通信避免暴露芯片唯一标识，日志、配置和传感器历史等用户数据按产品要求选择加密和匿名化策略。

开发与发布检查

  • 开发阶段保留可调试镜像，发布镜像启用签名、加密和版本校验。

  • OTA 必须验证镜像完整性、签名、版本和回滚状态，流程见 OTA 升级。

  • 禁止把密钥、令牌和 Wi-Fi 密码写入普通日志或明文配置文件。

  • eFuse 烧录、证书注入、量产恢复和安全审计工具：待开发。
