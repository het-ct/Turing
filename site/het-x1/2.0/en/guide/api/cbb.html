CBB API

The CBB API is organized by capability components, with dedicated pages providing an overview, processes, examples, and expected interfaces. Only header files that exist in the warehouse and have been verified by the current project can be used as stable APIs; the remaining interfaces remain “to be developed”.

Audio playback already has platform/services/audio/het_audio_play.h, and GUI components already have public header files under platform/middlewares/gui/components/include. The unified het_* API of communication, algorithm, charging, secure storage and other capabilities has different completeness. You should check CBB capability components and the actual project before use.

The public header files of audio playback and UI components have been included in Doxygen, and the remaining components are subject to the actual header files marked on the topic page.

The current CBB declaration with the stable het public header is shown in Service API and UI API; components with only planning names, intrinsic functions, or non-het interfaces do not generate APIs.
