FAQ
===

本页按“现象、检查、处理”的顺序汇总 MCU SDK 的常见问题。提交问题时请同时提供 SDK 版本、
板卡版本、完整构建日志、启动日志和可复现步骤。

编译器或 make 找不到
--------------------

**检查**：在新终端中运行工具链版本命令、``make --version`` 和 ``python --version``。

**处理**：确认工具目录已加入 ``PATH``，工程路径不包含脚本无法处理的特殊字符。重新执行
``python gen-srclist.py`` 后再编译，详细步骤见 :doc:`../get-started/environment`。

编译成功但没有 app.dcf
----------------------

**检查**：确认当前目录是目标工程，并检查第一条编译错误，而不是只查看日志末尾。

**处理**：目标文件默认位于 ``projects/<project>/Output/bin/app.dcf``。若目录不存在，核对
``inclist.mk`` 和工程功能开关是否由当前配置生成。

外设初始化失败
--------------

**检查**：记录 API 返回值、外设实例、管脚复用、时钟、电源、总线地址和初始化顺序。

**处理**：先运行最小 HAL 示例，再逐层接入器件驱动和业务。片内外设入口见
:doc:`../api/index`，板级适配见 :doc:`../middleware/board-adaptation`。

显示正常但触摸无响应
--------------------

**检查**：分别验证触摸电源、复位、中断、IIC 地址与坐标方向，确认显示与触摸没有复用同一资源。

**处理**：先打印原始触摸坐标，再接入 UI 事件；旋转屏幕时同步检查坐标转换。控件事件模型见
:doc:`../widgets/index`。

升级后无法启动
--------------

**检查**：保留升级日志，核对目标分区、固件完整性、签名、板卡版本和试运行确认状态。

**处理**：停止重复覆盖可启动分区，按 :doc:`../get-started/ota-upgrade` 的异常路径恢复。
量产烧录器的强制恢复操作与分区恢复包：**待开发**。
