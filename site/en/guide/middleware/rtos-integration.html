RTOS and task model

: Current engineering examples combine business functions with tasks, timers, interrupts, and event callbacks, but the repository has not yet provided independent, stable universal RTOS adaptation documentation. Different projects may use different schedulers, locks, and memory policies, so you cannot directly apply Linux threads or Android Handler models.

It is recommended that constrained

  • interrupts only complete sampling, clearing, and delivering events, and time-consuming calculations should be placed in the task or CBB work queue.

  • Clarify the invocation context for each HAL/CBB API: initialize task, normal task, interrupt, or callback.

  • Labeling ownership, lifecycle, cache consistency, and alignment requirements for DMA buffers.

  • Watchdog, low power, and abnormal recovery are uniformly orchestrated by product applications.

Pixso

  • Supported RTOS list, porting layer interfaces, task templates, IPC, locks, and memory allocation policies: To be developed.

  • Task scheduling sequence diagram, performance metrics, and thread safety API annotations: To be developed.
