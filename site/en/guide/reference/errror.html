Unified Error Model

het_err_t is int32_t. The interface return value convention is: ret > 0 indicates success (usually the number of transmitted bytes or 1), ret == 0 indicates failure or no progress, ret < 0 indicates a structured error with severity level, layer, module, and details.

Reference het_button.c: Boundaries between event return values and error codes

platform/middlewares/gui/components/src/het_button.c is an example of component event handling. It uses HET_OBJ_RET_CONSUMED and HET_OBJ_RET_PASS to indicate whether a message was consumed by the current object. Such return values represent the result of event dispatching, not het_err_t error codes.

The button implementation validates the object, updates the state, and dispatches events using HET_CAST_OBJ and het_event_notify; if the underlying HAL call fails, the corresponding HET_ERR_* should be returned at the HAL/API boundary, with the upper-level event handler deciding whether to log, retry, degrade, or convert it into a business message.

Example of unified error code usage

Design and usage constraints

  • New module errors should preferably use HET_ERR_MAKE(sev, layer, module, detail) and should not randomly return uncategorized negative numbers.

  • The error level should reflect the actual layer where the error occurs and should not rewrite HAL errors as APP layer errors just because the caller is in the App.

  • When forwarding across layers, retain the original het_err_t. Use logs or wrapper structures to add context, without losing severity/layer/module/detail.

  • Callback, event, and ISR scenarios must clarify the thread context and lifecycle of error codes; do not perform blocking recovery in ISR.

  • Each new error detail should be simultaneously updated in the corresponding module header file, documentation, and test cases.

static het_obj_ret het_button_send(het_button_t *obj,
                                   const het_event_code signal,
                                   het_event_t *const evt)
{
    if (het_obj_check_center(widget_get_absolute(obj->parent.src.obj),
                             *(const point_t *)HET_EVT_GET_POS(evt))) {
        het_event_notify(&obj->cb, obj, HET_EVENT_TYPE_NORMAL,
                         signal, evt->param);
        return HET_OBJ_RET_CONSUMED;
    }
    return HET_OBJ_RET_PASS;
}

#include "het_err.h"
#include "het_gpio.h"

int init_button_gpio(void)
{
    het_gpio_handle_t cfg = het_gpio_def_cfg();
    het_err_t ret = het_gpio_init(&cfg);
    if (HET_ERR_IS_NEG(ret)) {
        uint32_t severity = HET_ERR_GET_SEVERITY(ret);
        uint32_t layer = HET_ERR_GET_LAYER(ret);
        uint32_t module = HET_ERR_GET_MODULE(ret);
        uint32_t detail = HET_ERR_GET_DETAIL(ret);
        log_error("GPIO init failed: sev=%u layer=%u module=%u detail=0x%04x",
                  severity, layer, module, detail);
        return ret;
    }
    return HET_OK;
}

/* 对于返回传输数量的 API，按其头文件约定判断： */
int send_frame(const uint8_t *data, uint16_t len)
{
    int ret = het_spi_write(HET_SPI_ID_1, data, len);
    if (ret < 0) {
        /* 可按 HET_ERR_GET_* 解析结构化错误。 */
        return ret;
    }
    return ret; /* ret > 0 通常表示成功传输的字节数。 */
}
