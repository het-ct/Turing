Versions, downloads, and deliverables

SDK delivery should treat source code, tools, hardware documentation, and version records as a unified controlled baseline. Do not send only one firmware file, otherwise the recipient cannot confirm whether the toolchain, board, and resource versions match.

version rules

includes at least the SDK version, Git commit, build date, toolchain version, supported boards, known limitations, and upgrade compatibility. When firmware, resources, and configurations change, their compatibility relationships should be clearly defined. Document versions are managed by metadata.json’s doc_versions. For construction methods, see the project document release notes.
