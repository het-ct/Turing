驱动与 BSP

概述

platform/bsp 把 HAL 映射为可直接使用的板载器件能力，包括显示、触摸、摄像头、音频、 传感器、Flash、按键、充电、USB 和网络。驱动必须隔离器件差异，不把产品业务写入总线层。

接入流程

  1. 确认器件电源、复位、总线、地址和中断连接。

  2. 先用 HAL 验证总线读写，再接入器件初始化表。

  3. 在 BSP 中实现 init/read/write/deinit 或现有模块约定的接口。

  4. 将器件型号和管脚选择放入 config.h。

  5. 验证冷启动、热复位、总线异常、低功耗恢复和长时间运行。

现有驱动

显示和触摸驱动位于 platform/middlewares/gui/tft 与 platform/middlewares/gui/ctp；摄像头 适配位于 platform/bsp/bsp_image_sensor；传感器驱动位于 platform/bsp/bsp_sensor。

驱动使用要点

  • 显示：先上电/复位，再配置总线和窗口，最后开启背光与刷新。

  • 触摸：先确认 IIC 地址、INT/RST，再处理坐标方向和屏幕旋转。

  • 摄像头：配置时钟、帧格式和缓冲区，帧处理完成后及时归还 DMA 缓冲。

  • 音频：设置采样率、增益和输入输出通道，播放循环中调用处理函数。

  • 传感器：先探测设备 ID，再执行校准和周期读取，异常时释放总线。

公共 het API 见 API 参考；BSP 的器件专用 bsp_* 接口只作为实现细节参考， 不在 API 参考范围内。

示例

int sensor_probe(void)
{
    /* 先验证总线，再进入器件初始化，避免吞掉 NACK。 */
    int ret = bsp_i2c_init();
    if (ret < 0) return ret;
    return bsp_sensor_init();
}

主要 API

BSP 尚未形成统一公开 API 清单，当前以各 bsp_*.h 为准；稳定的公共头文件、错误模型和 线程安全说明 待开发。
