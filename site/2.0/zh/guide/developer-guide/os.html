OS 与任务模型

概述

软件分层图中的 L3 对应 OS/OSAL。它为 L4 中间件、L5 CBB 和产品应用提供统一的并发与系统资源模型， 让业务只描述任务和消息，不感知具体 RTOS 的线程控制块、调度器和时钟实现。当前工程的完整 OSAL 端口 仍在建设中，未实现的后端和配置项标记为 待开发。

线程管理

一个任务对应一个职责清晰的循环：初始化资源、等待事件、处理有限工作量、释放或休眠。线程优先级、栈大小、 栈检查和看门狗策略由产品统一配置；禁止在高优先级任务中执行无界循环或大块 Flash/网络操作。

任务通信

任务之间使用队列、事件标志或消息邮箱传递数据，明确消息所有权、长度和超时。中断只投递短消息或索引， 由任务完成解析、绘制和存储。队列后端、事件组和邮箱的统一 API 待开发。

软件定时器

软件定时器适合周期采样、超时重试和 UI 刷新等轻量工作；回调不应阻塞，也不应直接执行大块计算。复杂工作 应在定时器回调中投递消息，再由专用任务处理。定时器创建、启动、停止和删除接口 待开发。

内存管理

任务栈、消息队列和动态对象应在配置阶段估算并保留余量。长期对象使用明确的创建/销毁配对，DMA 缓冲区 遵循对齐和缓存一致性要求；中断上下文禁止动态分配。片上 SRAM、PSRAM 与代码段规划见 内存与存储管理。

使用示例

下面示例表示推荐的“中断投递、任务处理”模型；具体函数名随 OSAL 移植包发布后确定。

static void uart_isr(void)
{
    uint8_t event = UART_RX_EVENT;
    osal_queue_send_from_isr(uart_queue, &event, sizeof(event));
}

static void uart_task(void *arg)
{
    uint8_t event;
    for (;;) {
        if (osal_queue_receive(uart_queue, &event, sizeof(event), OSAL_WAIT_FOREVER))
            app_handle_uart_event(event);
    }
}

注意事项

  • ISR 与普通任务使用不同的发送接口，不能在 ISR 中等待资源。

  • 任务删除前先停止定时器、释放队列和注销回调。

  • 共享数据使用互斥锁或原子操作保护，禁止依赖任务切换时序。

  • OSAL 端口移植、线程 API、队列 API、软件定时器 API 和内存 API：待开发。
